1. The Wedge & Problem Statement

Problem Statement

  • Conventional payment rails (card networks, custodial wallets, cloud APIs) assume continuous, bidirectional internet connectivity between transacting parties.
  • Orbital and remote assets operate on intermittent, high-latency, low-bandwidth links: short ground passes, LoRa store-and-forward at ~1 kbps, no TCP/IP end-to-end.
  • No existing settlement protocol fits a cryptographically verifiable payment intent into the physical ceiling of a 255-byte LoRa PHY frame on a microcontroller that cannot allocate heap.
  • Result: edge assets (satellites, remote sensors, air-gapped devices) cannot autonomously buy or sell services (data, fuel, compute) — there is no trustless commerce layer below the connectivity line.
  • Void Protocol's answer: an asynchronous Store-and-Forward settlement protocol — a Layer 2 M2M protocol where a signed payment intent travels over a disrupted link, is verified at the ground segment (bouncer), settled on an L2 blockchain, and the signed receipt is delivered back asynchronously. Entities: Sat A (Seller) broadcasts invoices; Sat B (Buyer/Mule) encapsulates and signs payment intent with hardware identity keys (Ed25519); the Ground Station is the L2 authority that validates signatures, batches settlements, and issues the unlock.

The Shift / Catalyst

  • Cheap, fast L2 blockchain finality (Arbitrum/Base-class networks) makes asynchronous settlement economically viable per-transaction.
  • Commodity edge hardware: ESP32-S3 (Heltec WiFi LoRa 32 V3, ~$30-class) with SX1262 LoRa radios puts a signing, transmitting settlement node within hobby budgets.
  • TinyGS: a free, global community ground-station mesh that can ingest community-tier (SNLP) frames — zero-cost network rollout for adoption.
  • Small-satellite proliferation (PocketQube, university CubeSats) creates demand for per-asset, per-transaction monetization of orbital services.
  • Scale stat: the protocol's 32-bit sat_id addressing supports 4.2 billion global DePIN edge identities.

Target Operator / ICP

  • Community tier: amateur radio operators, university small-sat labs, TinyGS station owners, high-altitude balloon (HAB) and remote-sensing operators on ISM bands — adoption play, Apache 2.0, "clone and run".
  • Enterprise tier: defense and commercial satellite operators (licensed bands: S-Band, X-Band, Link-16, phased array), fleet operators needing multi-session multiplexing (50+ concurrent connections), identity authority (key rotation, revocation, reputation scoring), high-frequency settlement batching with MEV protection, and factory key provisioning (ATECC608/SE050 chips).
  • Commercial model: Open Core — "Thick Client, Thin Server": all device-side code is OSS to drive standard adoption; coordination of many nodes (identity, settlement aggregation, fleet analytics) is the proprietary Enterprise product. Rule of thumb: optimizing one node is Open Source; orchestrating many nodes is Enterprise.

2. System Architecture & Topology

High-Level Layout

  • void-core/ — pure C++14 protocol layer, zero hardware dependencies; packet structs (void_packets.h, void_packets_ccsds.h, void_packets_snlp.h), security_manager (Ed25519/X25519/ChaCha20/SHA-256 via libsodium), pure-function builders (packet_d_builder, heartbeat_builder).
  • satellite-firmware/ — PlatformIO entrypoints for the Heltec V3; compiles two roles from one codebase: seller (invoice beacon, Packet C RX → Packet D delivery emission + UNLOCK display) and buyer (Packet A capture → signed Packet B TX, Packet D delivery display), plus synthetic GPS stub and heartbeat TX.
  • ground-station/ — desktop C++14 bouncer: serial_hal (USB serial), Bouncer (Ed25519 verify, length-check-first), gateway_client (zero-heap HTTP POST), ack_builder (ACK emission), egress_poll_client + template-based egress orchestrator (static dispatch, no virtual functions, no heap); ground-station/ui/ — Dear ImGui operator console (4 fixed panels).
  • gateway/ — Go 1.25 Web3 router: gin HTTP server on :8080, Kaitai-generated parser, Ed25519 verifier, satellite registry, EscrowClient + BufferedSubmitter (batch 10 / 5 s, retry-once) via go-ethereum, receipt.Store (append-only JSONL), chain.Watcher (SettlementCreated poll every 2 s), telemetry store (heartbeats).
  • contracts/ — Foundry project; Escrow.sol with settleBatch (max 10, USDC-only, duplicate-nonce guard, SettlementCreated event); runs on local Anvil chain (chain ID 31337) for the flat-sat; testnet promotion is Phase B.
  • docs/kaitai_struct/ — canonical Kaitai Struct schema (.ksy): the source of truth for the wire format; the Go parser is auto-generated from it.

Wire Protocol & Packet Structures

Dual-tier framing multiplexed by sync word — SNLP community tier (14-byte header, sync word 0x1D01A5A5, ISM/LoRa/TinyGS bands) and CCSDS enterprise tier (6-byte primary header, CCSDS 133.0-B-2). Headers are Big-Endian; payloads are Little-Endian; all multi-byte fields pack/unpack via bit-shifting.

Packet types and frame sizes by tier
PacketCCSDS frame (6 B hdr)SNLP frame (14 B hdr)Purpose
A Invoice72 B80 BService offer from Sat A
B Payment184 B192 BEncapsulated, signed payment intent
C Receipt104 B112 BSigned proof-of-execution from Sat A
D Delivery128 B136 BReceipt delivery to ground ledger
H Handshake112 B120 BEphemeral X25519 ECDH key exchange
ACK120 B136 BGround-to-sat unlock/acknowledgement
Heartbeat (L)40 B48 BLoRa beacon/telemetry frame
TunnelData88 B96 BEncrypted tunnel payload

All frame sizes satisfy sizeof % 8 == 0 and <= 255 (SX1262 LoRa PHY payload ceiling); values from void-core/include/void_packets.h; flat-sat alpha flies SNLP plaintext only.

Data Flow

  1. Seller Heltec broadcasts Packet A (Invoice) over LoRa.
  2. Buyer Heltec validates terms, wraps a payment intent into Packet B, signs it (Ed25519 over header + body[0..105]) and transmits.
  3. Ground bouncer (desktop C++) receives the frame over USB serial, verifies length then signature, forwards the raw frame to the gateway via HTTP POST /api/v1/ingest.
  4. Gateway pre-validates CRC32, parses the frame with the Kaitai parser, verifies the Ed25519 signature against the satellite registry, and enqueues the settlement intent.
  5. BufferedSubmitter batches up to 10 intents and calls settleBatch on the Escrow contract (local Anvil); the transaction mines and emits SettlementCreated.
  6. chain.Watcher detects the event; the receipt processor builds and signs Packet C, appends the record to receipts.json (append-only JSONL, crash-safe).
  7. Bouncer polls GET /api/v1/egress/pending, relays Packet C to the seller over LoRa, and ACKs the gateway (POST /api/v1/egress/ack → DISPATCHED).
  8. Seller verifies the receipt, displays UNLOCKED, and emits Packet D (Delivery); buyer receives and displays DELIVERY RECEIVED. Heartbeat (Packet L) beacons throughout for telemetry.

3. Defensibility & Hard Metrics

Engineering Constraints

  • Zero-heap allocation: malloc, new, free, calloc, realloc are banned in all C++ — eliminates heap fragmentation by construction.
  • No dynamic strings: std::string and Arduino String banned; const char* + snprintf with bounded buffers only.
  • No VLAs, no C-style casts; reinterpret_cast only after length AND header-ID validation ("length check first, struct cast second" — VOID-112 invariant).
  • Zero-copy deserialization: payloads parsed directly from static buffers via APID header peeking and exact-length validation before pointer cast; the Go gateway likewise parses raw frames directly from http.Request.Body with no intermediate JSON.
  • Const-correctness mandatory; static persistent buffers; stack allocation for small short-lived values.
  • Compile-time enforcement on BOTH firmware and desktop builds: -Wall -Wextra -Werror -Wshadow -Wvla -Wconversion -Wsign-conversion -Wcast-align -Wold-style-cast -Wformat-security -O2 -D_FORTIFY_SOURCE=2 — non-compliant code fails the build, so the memory-safety posture cannot silently degrade at the gateway boundary.

Wire Efficiency & Compile-Time Packet Guarantees

  • Every over-the-air struct is #pragma pack(push, 1) + __attribute__((packed)), and carries two static asserts: 8-byte machine-cycle alignment and the 255-byte SX1262 LoRa PHY payload ceiling. Tail padding is an explicit zeroed _tail_pad[N], never accidental.
  • The two static asserts, as enforced on Packet B: 
    static_assert(sizeof(PacketB_t) % 8 == 0, "8-byte frame alignment");
static_assert(sizeof(PacketB_t) <= 255, "LoRa PHY payload ceiling");
  • Locked wire-format invariants (enforced byte-identically across C++, Go, and the Kaitai schema):
    • Nonce (VOID-110): ChaCha20 nonce derived as sat_id[4] || epoch_ts[8] (12 bytes) on both ends — never transmitted; zero wire bytes reserved for it.
    • Signature scope (VOID-111): Ed25519 covers header + body[0..105] for Packet B (packetBSigScopeBody = 106), accessed via offsetof, identical across tiers.
    • Bounds check (VOID-112): packetBBodyLen = 178; ingest rejects under-sized buffers with HTTP 400 before any struct cast.
    • SNLP header (VOID-113): exactly 14 bytes, sync word 0x1D01A5A5; CCSDS header exactly 6 bytes.
    • Frame alignment (VOID-114B): every frame total % 8 == 0.
    • Endianness: Big-Endian headers, Little-Endian payloads, packed/unpacked exclusively via bit-shifting — never raw memory mapping.
    • CRC pre-validation (VOID-122): global CRC32 verified for PacketD and ACK (both tiers) after magic-byte routing, before any body field is trusted — RF bit-flips cannot misroute a handler.
  • Deterministic golden vectors: checked-in .bin wire vectors for all 8 packet types in both tiers (test/vectors/ccsds/, test/vectors/snlp/); builders on both C++ and Go sides must be byte-exact; cross-tier signature-parity and sig-scope boundary tests pin the format.

Barrier to Entry

  • The moat is the combination, not any single part: defense-grade memory-safety discipline (targeting NSA/CISA + SEI CERT) on a microcontroller, plus blockchain settlement engineering, plus RF/wire-format engineering — three rare specialisms in one team.
  • Cross-language byte-identity: the same wire invariants hold in C++ firmware, the Go gateway, and the canonical Kaitai schema — replicating it means re-deriving every offset, scope, and assert, not gluing off-the-shelf MQTT + crypto libraries.
  • Compliance posture as product: pre-certification engineering to NSA/CISA Memory Safety and SEI CERT C++ standards with compiler-enforced rejection — unreplicable with general-purpose web stacks where heap allocation and GC pauses are acceptable.
  • Open-core distribution: the OSS thick client is designed to become the standard (unrestricted amateur/university adoption), while network coordination (identity authority, high-frequency batching, MEV protection, factory provisioning) is proprietary — the adoption engine itself widens the moat.
